# Shared survey reads

The public endpoint is
https://survey-reads-counter.frankdou.workers.dev/hit.

## Counting and the Safari fix

The counter records **page views**, not verified unique readers. Each successful
page load or refresh adds one view. Switching between Full Paper, Benchmark, and
Case Archive within the same page does not add another view.

Busuanzi identifies a page using its Referer header. Safari's tracking protection
[reduces cross-site referrers to the origin](https://webkit.org/blog/9661/preventing-tracking-prevention-tracking/),
which previously split the survey's count between these two keys:

- Desktop: https://mit-cdfg.github.io/Survey-AI-for-3D-modeling-Robotics/
- Safari: https://mit-cdfg.github.io/

The Worker always supplies the first URL to Busuanzi, regardless of the client's
platform, fragment, query parameters, or referrer policy. This keeps the existing
desktop page-view total; it does not create a new counter, seed a database, or add
the unrelated origin-wide count. The frontend uses only this endpoint. All three
badges show its returned page count.

The old browser-local increment fallback is removed. Loading or failed requests
show an em dash with a status tooltip. Legacy local
counts are ignored, including counts generated by the old fallback. Failed hit
requests are not automatically retried because the upstream service might have
already counted the visit before its response was lost.

## Worker

- POST /hit: record one page view and return its total.
- GET /health: check configuration without recording a view.
- OPTIONS /hit: CORS preflight; does not record a view.

Only the survey's GitHub Pages origin may call /hit. The Worker accepts no
caller-selected page URL. It parses the upstream JSONP as data without executing
it, validates page_pv, and returns HTTP 502 on failure instead of a false zero.
The Worker does not store visitors or forward browser cookies or user agents.
It needs no KV/D1 binding and introduces no counter migration.

## Development and deployment

Run the regression tests with Node.js 22 or newer:

    node --test tests/reads-counter.test.mjs

Tests mock all upstream requests; they do not inflate the public count. Local
website previews do not call the live counter. For browser tests, set
window.CF_COUNTER_URL to a mocked endpoint before the counter script executes.

Deploy the Worker with the owner's existing Cloudflare login:

    cd cloudflare
    npx wrangler whoami
    npx wrangler deploy

Check GET /health before publishing the frontend. If the Worker URL changes,
update js/reads-counter.js. Keep the versioned script reference and badge markup
in both index.html and build_website.py; bump the script version when changing
its endpoint or behavior.

This service continues to depend on Busuanzi availability. There is no read-only
upstream API in this integration, so POST /hit must not be polled to refresh an
already open badge: that would add visits. Two pages opened at different moments
can show adjacent totals because each visit itself increments the shared count.
